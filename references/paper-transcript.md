# 论文式文字稿

只在用户明确要求论文式、摘要卡片，或按播客目录分章节时读这份。普通「转文字稿」不读、不写。

样稿：`D:\iStall\CapsWriter-Offline\work\XMind_Mango_分活_分圈_分钱_搞_AI\论文式文字稿.md`。样稿只说明结构。新节目的结论必须来自那一集自己的转录。

## 为什么这样切

网页目录是节目已经公开的章节，用来切段，避免模型自己发明小标题。转录才是证据。网页介绍、shownotes 里的人名、头衔、数字，如果转录没说，就不能写进摘要。2026-10-24 那一集的反例：网页写「二十年」「任鑫」，转录说的是「十几年」，主持人也没有报出那个名字。标题可以沿用网页目录，冲突写进适用边界，不要把网页说法改写成正文事实。

## 步骤

1. 确认同目录已有 `chapters.md`，并看过校验行数和缺失数。没有校验通过的转录，不要先写摘要。
2. 核对 `toc.json` 的章节数、标题、起止时间是否和网页目录一致。不一致时，以网页目录为准重切，仍然不改识别词。
3. 在该集目录写 `摘要卡片.md`。只根据 `chapters.md` 概括，3 到 5 条结论。
4. 用脚本拼成 `论文式文字稿.md`，不要手工重写正文：

```powershell
python "$HOME\.agents\skills\podcast2md\scripts\build_paper_transcript.py" `
  --episode-dir "<该集目录>" `
  --card "<该集目录>\摘要卡片.md" `
  --title "<从转录概括出的论文题，不是节目原标题的复读>" `
  --subtitle "<节目原标题>：对谈文字稿的论文式整理"
```

5. 默认把论文式文字稿和摘要卡片留在该集目录。用户没有明确要求另存时，不要复制到项目目录、桌面或其他 work。用户明确要求另存时，只复制用户点名的那一份最终稿：只点名论文就只复制论文，只点名摘要就只复制摘要，不要把没点名的那一份一起复制。不搬动、不删除原始音频和转录，也不改 CLI 的 `--out-dir`。目标已有同名且内容不同时，按主文停下、不覆盖。源路径和目标路径相同时，不算另存，不要重写。目标已有相同内容时，不要再覆盖，直接说明已在。复制失败或未执行时，不要报告成功。用户没给出目标路径时，不要猜测路径。
6. 交付时说明路径、章节数、校验结果，以及识别稿的限制：无说话人分离，专名和数字可能有误差。

## 摘要卡片

写成表格，字段固定：

| 项目 | 内容 |
|---|---|
| 题名 | 节目原标题 |
| 来源 | 单集页面。嘉宾身份只写转录里本人或主持人说出的话 |
| 嘉宾 | 转录里的称呼。稿中没稳定报出的主持人不补网页姓名 |
| 时长 | 用章节切分终点或音频时长，写明来源 |
| 核心问题 | 这一集实际在回答的问题，一句到三句 |
| 结论 1–5 | 每条都能在正文里找到对应说法。不要把网页介绍改写成结论 |
| 关键词 | 从转录里的概念取，不另造框架 |
| 适用边界 | 写明未润色、无说话人分离、正文不改识别词。标题和正文冲突、可疑数字，点名写在这里 |

结论用「对谈里说」「被用来说明」这类转述，避免把识别误差写成已核实事实。

## 正文规则

- 节标题用网页目录的时间和标题，中文序号「一、」起。
- 不删句、不换词、不润色改义。句末标点和分段交给脚本。
- 片尾音乐、英文歌词留在最后，标明不是对谈。
- 脚本只做机械分段。摘要卡片仍由模型写，因为那是判断，不是拼接。
